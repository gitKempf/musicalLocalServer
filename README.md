# Musical.run Local Server

Privacy-first local development server for Musical.run. Run Claude-powered app generation entirely on your own machine with end-to-end encryption.

## Quick Start

### One-Command Installation

```bash
curl -fsSL https://musical.run/install.sh | bash
```

Or download and run manually:

```bash
git clone https://github.com/yourusername/musical-backend.git
cd musical-backend/local-server
./install.sh
```

### Manual Installation

**Requirements:**
- Docker Desktop (Mac) or Docker + Docker Compose (Linux)
- 4GB RAM minimum
- 10GB disk space

**Steps:**

1. Clone the repository:
```bash
git clone https://github.com/yourusername/musical-backend.git
cd musical-backend/local-server
```

2. Start services:
```bash
docker compose up -d
```

3. Verify health:
```bash
curl http://localhost:17100/health
```

## CLI Commands

After installation, use the `musical-server` command:

```bash
musical-server start       # Start the local server
musical-server stop        # Stop the local server
musical-server restart     # Restart the local server
musical-server logs        # View logs (all services)
musical-server logs <svc>  # View logs for specific service
musical-server status      # Check service status
musical-server update      # Update to latest version
musical-server cleanup     # Clean up old Docker images
```

## Features

### 1. OAuth Authentication
- Browser-based OAuth flow with Musical.run
- Automatic token refresh
- Secure token storage in `~/.musical/auth.json`

### 2. SSH-Tunneled Terminal Access
- Full PTY/bash terminal access to Claude agent container
- WebSocket-based real-time communication
- xterm.js terminal emulation
- Terminal resize support
- Mobile-optimized UI

### 3. Git MCP Integration
- Automatic code commits from Claude
- Git operations exposed as MCP tools
- Seamless Gitea integration
- Version control for all generated code

### 4. End-to-End Encryption
- libsodium encryption (NaCl)
- Zero-knowledge architecture
- Keys generated locally
- Messages encrypted before transmission

### 5. Tunnel Integration
- Optional Cloudflare tunnel for remote access
- Automatic tunnel URL sharing
- QR code for easy mobile connection

## Services

### Local Server (Port 17100)
- Express.js API server
- Socket.IO for WebSocket
- Static file serving (terminal.html)
- Health check endpoint

**Endpoints:**
- `GET /health` - Health check
- `GET /terminal.html` - Terminal emulator
- `POST /auth/login` - OAuth login
- `POST /auth/refresh` - Token refresh
- `GET /api/tunnel/status` - Tunnel status
- `POST /api/tunnel/start` - Start tunnel
- `POST /api/tunnel/stop` - Stop tunnel

### Claude Agent Container
- Claude CLI pre-installed
- SSH server (port 22)
- Git MCP server
- Node.js runtime
- Isolated execution environment

**SSH Access:**
```bash
ssh root@localhost -p 2222
Password: musical
```

### PostgreSQL (Port 5432)
- User data storage
- Project metadata
- Commit history

### Gitea (Port 3000)
- Git repository hosting
- Web UI for code review
- Webhook integration
- User authentication

## Configuration

### Environment Variables

Located in `~/.musical/.env`:

```bash
# PostgreSQL
POSTGRES_USER=musical
POSTGRES_PASSWORD=<auto-generated>
POSTGRES_DB=musical_local
DATABASE_URL=postgresql://musical:musical@postgres:5432/musical_local

# Gitea
GITEA_ADMIN_USER=musical
GITEA_ADMIN_PASSWORD=<auto-generated>
GITEA_ADMIN_EMAIL=admin@musical.local

# Local Server
LOCAL_SERVER_PORT=17100
NODE_ENV=production

# OAuth (filled after first login)
MUSICAL_ACCESS_TOKEN=
MUSICAL_REFRESH_TOKEN=
MUSICAL_USER_ID=
```

### Data Directories

```
~/.musical/
├── auth.json           # OAuth tokens

├── data/               # PostgreSQL data
├── logs/               # Service logs
├── config/             # Configuration files
├── docker-compose.yml  # Docker Compose config
└── .env                # Environment variables
```

## Troubleshooting

### Local Server Not Starting

**Check Docker:**
```bash
docker ps
docker compose ps
docker compose logs musical-local
```

**Verify health:**
```bash
curl http://localhost:17100/health
```

### Terminal Connection Failed

**Check SSH server in Claude agent:**
```bash
docker exec musical-claude-agent pgrep sshd
docker exec musical-claude-agent ps aux | grep sshd
```

**Test SSH manually:**
```bash
ssh root@localhost -p 2222
# Password: musical
```

**Check WebSocket connection:**
```bash
curl http://localhost:17100/terminal.html
```

### OAuth Authentication Failed

**Check auth service:**
```bash
curl http://localhost:3001/health
docker compose logs auth-service
```

**Verify token storage:**
```bash
cat ~/.musical/auth.json
```

### Port Conflicts

**Change ports in docker-compose.yml:**
```yaml
services:
  musical-local:
    ports:
      - "17101:17100"  # Change host port
```

**Or stop conflicting services:**
```bash
lsof -i :17100
kill -9 <PID>
```

## Security

### Encryption
- All messages encrypted with libsodium
- Public key cryptography (X25519)
- Ephemeral session keys
- No plaintext storage

### Authentication
- OAuth 2.0 with Musical.run
- JWT tokens with expiration
- Automatic token refresh
- Secure token storage

### Network
- Local-only by default
- Optional Cloudflare tunnel for remote access
- HTTPS for tunnel connections
- WebSocket over TLS

### Container Isolation
- Docker container isolation
- No privileged containers
- Limited network access
- Read-only filesystem where possible

## Performance

### Resource Usage
- Memory: ~500MB idle, ~2GB during generation
- CPU: Minimal idle, spike during code generation
- Disk: ~2GB for Docker images, ~1GB for data

### Optimization
- Docker layer caching
- Shared npm cache
- Build-time TypeScript compilation
- Production dependencies only

## Uninstall

```bash
# Stop services
musical-server stop

# Remove containers and images
cd ~/.musical
docker compose down -v --rmi all

# Remove installation directory
rm -rf ~/.musical

# Remove CLI symlink
sudo rm /usr/local/bin/musical-server  # Mac
rm ~/.local/bin/musical-server          # Linux
```
